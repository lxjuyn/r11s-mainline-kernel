## 4. 救援 ramdisk（v10 切根契约）

- 源：`out/v15/ramdisk_v15.cpio`（**未压缩** newc cpio，23.2MB，含 adsp/cdsp/ath10k/BT/a530 固件）。
- `/init`（busybox sh）逻辑：
  - cmdline 无 root= → legacy v9（找 PARTNAME=userdata，btrfs subvol=@）；
  - cmdline 有 root= → 先起 ACM 救援 gadget（18d1:d004），轮询等块设备 ~30s，挂 ext4 rw,noatime 到 /newroot，校验 /newroot/sbin/init，解绑 gadget，move dev/proc/sys，`exec switch_root /newroot /sbin/init`；
  - **任何失败 → 救援 ACM shell，永不 panic/reboot**（防砖红线）。
- **关键坑（v16a 必须处理）**：init 的 root= 解析循环是**最后一次出现生效**；ABL 在 boot.img cmdline 之后追加 `root=/dev/dm-0`，会覆盖 `--root` 注入的值 → 直接用 `--root` 必然落到 dm-0 等待超时→救援 shell（v15b 现状即此）。
  **对策**：v16a ramdisk 的 init 增加最高优先级自定义参数 `r11root=`（有它优先于一切 root=），打包时 cmdline 带 `r11root=/dev/mmcblk1p69`，不动 ABL 行为，失败路径不变。
- init 脚本源文件未在工作区找到（仅存于 cpio 内）；已从 ramdisk_v15.cpio 解出（/tmp/rd15/），v16a 以此为基础打补丁并把源归档进 rootfs/ 目录纳管。

## 5. rootfs v3 现状（out/r11s_phase4a_rootfs_v3.ext4，192MB，debugfs 只读查）

- 有：`/lib/modules/7.0.14-sdm660-gcc++`（vermagic 与 v15b 匹配 ✓）；`/lib/firmware` 约 110 文件（ath10k/、mba.mbn、modem.b00-b28+mdt、qca/、qcom/）✓。
- 缺：`/sbin/init` 仅 5,536 B（自定义小脚本，**非 systemd**）；无 /etc/os-release；无 sshd、无 NetworkManager。
- **结论**：v3 是"最小验证 rootfs"，v16a 需新建 **v4 = Ubuntu Base 24.04 + systemd + openssh + NetworkManager + kmod/udev**，模块沿用同版本 modules_install，固件集可从 v3 提取复用（e2cp/debugfs，免挂载）。
